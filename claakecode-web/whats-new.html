§ what's new · v0.2.5

Share skills from any Git repo. Claake Code keeps them fresh.

Version 0.2.5 adds Git skill repositories: paste a repo URL and Claake Code clones it, reads every SKILL.md with a real YAML parser, dedupes mirror copies so a repo never conflicts with itself, and can auto-update by fresh clone. Below: the Claaky desktop companion, the 3D room and Kimi 3.1 Pro from 0.2.x.

00 · unreleased · next version

Fixes and additions on the way.

Shipped in version 0.2.8. Points marked untested or experimental are not verified as working.

security

Security

  • ✓Per-tool approval. Each tool has an "ask before running" switch (Settings > Tools). On a fresh install bash and python ask first. Approve once or for the rest of the turn; sub-agents and swarm teammates ask through the same prompt. Rust tests pass; the UI was not tried by hand.
  • ✓Write sandbox on macOS. bash, python and command guards can only write in the workspace, temp folders and a few caches (~/.cargo, ~/.npm, ~/.cache, ~/Library/Caches). Reads and network are not restricted. Switch in Settings > Tools. Tested on macOS, including a git commit inside a git worktree.
  • ✓Linux sandbox through bwrap: experimental, untested. It is written but was never compiled nor run.
  • ✓CLAAKE.md base rules are read from the home folder only, no longer from the opened project, and capped at 8,000 characters.
  • ✓Skill-repository auto-updates are now held as "pending": you see the changed files and accept or ignore. Manual updates apply directly as before.
agent loop

Agent loop

  • ✓edit_file is all-or-nothing: if one write fails, files already written are restored.
  • ✓Read-only tools (read, glob, grep, web search/fetch) from one model response run in parallel; tools that need approval never do.
  • ✓The skill catalog shows a one-line description per skill.
run engine

Run engine (guards)

  • ✓A skill can ship a graph.json: ordered steps, each with a guard checked on disk (file exists, file contains, git commit, command). You approve a graph once, by its SHA-256.
  • ✓When the model wants to end its turn, the guard decides; after 5 refusals you are asked to stop or continue.
  • ✓A step can be delegated to a sub-agent profile. Only the failure path is tested.
  • ✓Goal mode: optional verification command; update_goal is refused while it fails.
  • ✓Per-project "check after edit" command: its errors are shown to the model after a round that edited files.
learning

Learning

  • ✓A "Learning and recall" switch, global and per RLM chat.
  • ✓Every lesson carries its evidence. Statuses: candidate, validated, rejected. Only validated lessons are recalled in every chat (both harnesses); a candidate is recalled only in the conversation where it was born.
  • ✓An error fixed in front of a guard becomes a candidate lesson automatically, with the refusal reasons and changed files as evidence, without any model call.
  • ✓Agent bench: 20 small Python tasks judged by a command. A lesson is validated only if the pass rate with it is not lower than without it (3 runs each). The bench has only been run with a scripted fake model, never with a real model.
  • ✓Lessons screen in Settings > Persistent Python: list, edit (goes back to candidate), delete, validate, import from RLM memory, and 14 base lessons (from the ponytail and caveman skills and from errors met on this project) imported as candidates.
  • ✓Above 20 validated lessons, the ones sharing the most words with the request are recalled first (simple word overlap, no learned model).
rlm

RLM / Auto Compute

  • ✓Fix: the bundle now ships prime-agent-runtime, without which the persistent Python kernel could not be installed. The fix is written; the kernel start was not observed, and it needs a new release.
  • ✓Auto Compute passes the last 6 tool results and the list of uncommitted files, and a button sends the result back to the source chat's composer without sending it.
docs and checks

Docs and numbers

The README no longer claims to be "the only coding agent" for clean_context / todo_list. The app crate has 341 Rust unit tests and the desktop crate 44; the TypeScript check is clean.

01 · git skill repositories

One URL. Every skill in the repo.

Point Claake Code at a Git repository of skills. It clones the repo, discovers every SKILL.md and lists the skills in Settings, ready to hand to the agent. No packaging, no registry - if it is a Git repo, it works.

  • ✓Real YAML parsing. Multi-line description: > and | blocks are read in full, never truncated to a stray >.
  • ✓No self-conflicts. A repo that keeps mirror copies (like skills/ and .openclaw/skills/) is deduped: one copy wins, the rest become "duplicate ignored" warnings - never a name conflict.
  • ✓Auto-update by fresh clone. Opt in per repo; Claake Code checks at launch and every 6 hours, then swaps in a clean clone only after it validates. A broken upstream never touches your working copy.
  • ✓Update all. One button checks every enabled repo and updates only those with something new, then reports what changed.
01 · desktop companion

A little helper that floats above your work.

Claaky lives on your desktop, always on top. Drag him anywhere: his position is remembered. He reacts in real time to the seven states of the agent: idle, thinking, working, planning, done, error and sleeping.

  • ✓Click Claaky to open a frosted-glass chat bubble. It opens to the left when he sits on the right half of the screen.
  • ✓Ask mode answers directly, without tools and without opening Claake Code.
  • ✓Code mode hands the task to Claake Code and opens it if needed.
  • ✓Paste text or capture an area of the screen (macOS), then ask about it.
  • ✓The companion keeps its own history. Continue in Claake Code picks a conversation up in the IDE.
shortcut

⌃ ⌥ Space

A global shortcut opens the bubble from any app. You can change it in Settings; the old Alt+Space shortcut is migrated automatically.

always there

Menu bar and Workspace

Show or hide Claaky from the menu bar icon or the Claaky button in the Workspace. Closing the main window keeps him running; Cmd+Q quits.

settings

Yours to tune

Choose the shortcut, the default mode, which models the companion may use, and whether it starts when you log in.

02 · Claaky's 3D room

See what the agent does, at a glance.

Inside the IDE, Claaky now has his own animated 3D room, with warm, cosy lighting and a layout faithful to the original illustration. Every agent state has a place in the room.

  • ✓He types at his desk while the agent works, thinks in front of the whiteboard, and sleeps under a blanket when nothing happens.
  • ✓He teleports between spots with a soft fade, instead of walking across the room.
  • ✓When a test fails, the test machine flashes orange.
  • ✓Lighter than before: 7 animations instead of 20, and 3 MB of images instead of 13 MB.
  • ✓Images load only when needed, and only the part of the scene that changes is redrawn.
