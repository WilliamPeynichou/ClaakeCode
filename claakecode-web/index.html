02 / RLM Prime · Expérimental

Un second chat.
Un Python persistant.

RLM utilise le moteur Prime Agent dans un onglet distinct du chat classique. Les variables Python restent disponibles entre les exécutions d’une même session.

macOS et Linux seulement. Pas de RLM sur Windows.

Ce qui change

Chaque conversation RLM dispose de son historique et d’un worktree Git. Auto Compute ouvre un chat RLM depuis un chat classique et lui transmet du contexte ; le résultat peut être repris dans le brouillon du chat d’origine.

Ce qu’il faut prévoir

  • Un dépôt Git avec au moins un commit.
  • Une connexion Anthropic, OpenAI, OpenRouter ou Mistral. Google, Kimi et xAI ne sont pas pris en charge dans RLM.
  • Des commandes exécutées avec vos permissions. Un worktree sépare les fichiers de travail ; ce n’est pas un bac à sable de sécurité.

Les tâches longues et le mode Goal restent à vérifier manuellement avec un vrai modèle. Un agent peut se tromper, s’arrêter ou consommer des tokens sans résoudre la tâche. Gardez les tests et la revue du code.

03 / Leçons et mesures

Garder une leçon.
Vérifier sa portée.

Des instructions, pas un modèle réentraîné

Les leçons conservent une règle et ses preuves, avec un statut candidat, validé ou rejeté. Elles se consultent, se modifient et se suppriment dans les réglages. Le rappel des leçons peut être désactivé.

Deux mesures à ne pas confondre

Le suivi des modèles mesure les tours, durées et tokens des sessions. Les coûts dépendent des tarifs saisis : ce sont des estimations, pas une facture ni un classement de qualité.

Le banc de test compare des exécutions avec et sans leçon sur de petites tâches Python, notamment via le moteur RLM. Le parcours complet avec un vrai modèle reste à vérifier : ces tests ne prouvent pas un gain sur tous vos projets.

06 / Questions utiles

Avant de
commencer.

Est-ce un outil gratuit ?

Le code de Claake Code est sous licence MIT. L’utilisation des modèles n’est pas incluse : elle dépend de vos clés API, abonnements, quotas et des conditions de chaque fournisseur.

Est-ce local, privé ou utilisable hors ligne ?

L’interface est une application desktop. Les requêtes et le contexte utile sont envoyés aux fournisseurs et services que vous configurez. L’utilisation de ces modèles nécessite une connexion réseau ; le traitement n’est pas entièrement local. Les outils terminal et les serveurs MCP peuvent aussi accéder au réseau.

Le chat classique et RLM ont-ils les mêmes accès ?

Non. RLM est expérimental, disponible sur macOS et Linux seulement, avec Anthropic, OpenAI, OpenRouter et Mistral. Le chat classique offre davantage de fournisseurs. Les possibilités dépendent aussi du modèle choisi.

L’agent peut-il travailler sans surveillance ?

Il peut enchaîner des outils et des étapes. Cela ne garantit pas une tâche terminée ni un résultat juste. Limitez ses permissions, contrôlez les commandes et les diffs, puis lancez vos tests. RLM n’est pas isolé par un bac à sable.

Les benchmarks prouvent-ils qu’un modèle est meilleur ?

Non. Les mesures de session décrivent votre usage. Le banc des leçons est limité à de petites tâches et n’a pas été validé avec un vrai modèle. Aucun des deux ne constitue un classement général des modèles.

Où signaler un problème ?

Ouvrez une issue GitHub en indiquant la version, le système et les étapes pour reproduire le problème. N’y joignez pas vos clés ni des données sensibles. Pour un problème de sécurité, consultez la politique de sécurité.
